# Sedona Studio Windows 0.7.0

Отдельный Windows-проект: G:\SedonaStudio-Windows. Основа — проверенный снимок /data/mikl/sedona-studio на Debian; upstream/snapshot.json содержит commit, время и SHA-256 каждого исходного файла, исходный архив и незакоммиченные изменения сохранены рядом. Это независимая Windows-копия; автоматической синхронизации нет.

Запуск: Start-SedonaStudio.cmd. Устанавливать Java не нужно. Сессии, пароли, кэши и черновики хранятся отдельно: %LOCALAPPDATA%\BCControl\SedonaStudioWindows. Старое хранилище SedonaStudio автоматически не импортируется. Настройки также имеют отдельное пространство.

Сохранены возможности Debian-редактора: редактор схемы и свойств, формулы asStr, локальные ширина/значки/информация блоков и подписи на схеме, темы/цвета/языки, тренды, сессии, импорт/экспорт SAX/SAB, симулятор, мастерская китов и загрузка/восстановление приложения. Записи требуют штатных явных действий; опция автоматического применения по умолчанию выключена.

В комплект входит классический Windows Sedona SDK со стандартными китами. Симулятор находит app/sdk рядом с приложением. В настройках можно выбрать другой совместимый SDK; киты должны совпадать по checksum. Киты Sedona и нативные C-киты собираются и тестируются локально из мастерской. В комплект включён LLVM-MinGW 20240619 с лицензиями; отдельно устанавливать C-компилятор, Python или Linux для этого не нужно. Локальная сборка C сейчас предназначена для комплектной VM Win32 с refSize=4. Другая архитектура SDK требует своей VM и scode.

Симулятор включается пользователем и останавливается при закрытии редактора. Комплектная классическая VM не поддерживает привязку SVM_INET_BIND и может слушать сетевые интерфейсы компьютера; доступ защищён случайным паролем конкретного запуска.

Сборка: python -X utf8 build.py. Проверки: python -X utf8 test.py --ui-smoke --local-sox --live-ui. Тесты используют только локальную VM, никогда реальный контроллер. Windows-пакет: python -X utf8 package_windows.py. Результаты проверок и SHA-256 — в releases/0.7.0.

В мастерской: «Новый кит» → «С нативными методами C» → область, поставщик и имя. Исходники создаются в app/sdk/src/studio-native/<область>/<имя>. Редактируйте Sedona/C в окне мастерской, затем «Собрать», «Тестировать», «В палитру». Кнопка симулятора запускает новую VM. Если симулятор уже работает, остановите и запустите его снова: работающая VM сохраняется до завершения процесса. Неудачная C-сборка сохраняет предыдущие кит, манифест и VM; журнал и ошибки с номерами строк остаются в мастерской. Поддерживается несколько нативных китов в одной VM. Сборки VM данного SDK сериализуются.

Для стороннего кита с C сначала перенесите его исходники в sdk/src/studio-native/<область>/<имя>, проверьте уникальность native id и совместимость C с Windows. Библиотеки и C-код для других ОС автоматически не портируются.

Действия на схеме во время фоновой операции ожидают её завершения. При смене структуры или ошибке операции очередь отбрасывается с сообщением в строке состояния: повторите действие. Это не повторяет записи в устройство.

Дополнительная проверка локального C: python -X utf8 test.py --native-windows. Комплектный .exe дополнительно проверяется сквозным сценарием мастерской C → палитра → симулятор. Старый выпуск 0.5.0 сохранён.


В 0.7.0 добавлены иконки типов по niagaraIcon в манифесте: палитра, дерево программы и заголовки блоков. Настройки → источник иконок: локальный icons-ux.jar либо каталог с путями module/resource (например icons/x16/control/util/sine.png). Модуль читается как ZIP только ради PNG, его классы не загружаются. Изображения кэшируются в фоне; при отсутствии ресурса используются собственные иконки категорий. Оригинальный набор Niagara/MCS в дистрибутив не включён.

Собственный значок теперь является пометкой экземпляра и отображается отдельно от иконки типа. В свойствах блока можно отдельно включить текст и выбрать комментарий экземпляра или описание типа; описание типа также находится в отдельной раскрывающейся секции. Старые комментарии и оформление сохранены. На блоке текст ограничен по высоте, полный текст доступен в подсказке.

Для заметок: правый щелчок → цвет и «Привязать к блоку». Привязанная заметка следует за блоком, копируется с группой и восстанавливается при отмене. При удалении блока заметка остаётся на холсте без привязки. Поиск программы ищет также текст заметок. В Настройках можно скрыть иконки типов либо заметки/текст блоков, не изменяя проект. SAX/SAB не переносит оформление; сохраняйте и обычный файл проекта.

При обновлении сохраняйте выбранный рабочий SDK: там находятся созданные киты и собранная для них VM. Смена версии редактора не должна заменять ваши исходники стандартным SDK из нового выпуска. Локальная настройка этого компьютера сохраняет SDK предыдущего выпуска и подключает изображения из установленного MCS.
