# Один проект с внутренними модулями

Корень всего проекта: G:\SedonaStudio. Редактор, панель, API, стенд, тесты и документация выпускаются вместе. G:\SedonaPanel сохранён только как архив прежней структуры; сборка не читает из него ни исходники, ни библиотеки, ни runtime.

## Структура

- src/main/java — редактор, модель, SOX и адаптер integration/panel.
- modules/panel-api/src/main/java — общий контракт API major 1.
- modules/panel-widgets/src/main/java — виджеты и документ панели.
- modules/panel-demo/src/main/java — тестовый стенд и имитация данных/команд.
- tests/panel — проверки внутреннего модуля.
- tools/build_panel.py и tools/test_panel.py — вспомогательные шаги общей сборки/проверок.

Граница API нужна для независимой работы над кодом панели, а не для разделения продукта. Виджеты не импортируют Project, History, SOX или пароли. Новые виджеты и раскладку можно писать здесь, не меняя редактор. Передача новых команд/возможностей меняет адаптер отдельно.

## Команды из общего корня

Полная сборка: python -X utf8 build.py. Она автоматически собирает API, виджеты, стенд и редактор. Ручного копирования или установки между проектами нет.

Только виджеты после первой полной сборки: python -X utf8 build.py --panel-only. Используется уже собранный API; JAR редактора не меняется. Общие проверки: python -X utf8 test.py — включают тесты API/виджетов и запуск стенда. Стенд разработчика: Start-Panel-Demo.cmd.

Один Windows-выпуск содержит редактор с панелью и служебный Panel-Demo.cmd. Один архив исходников содержит все внутренние модули. Общая JavaFX-библиотека и runtime используются из текущего проекта, без дублирования рабочего окружения. Подключаемый JAR по-прежнему лежит в app/modules; служебный стенд в app/panel-demo. Оба исключены из общего classpath редактора при упаковке.

## Поведение и текущие границы

Вкладка «Панель» справа содержит начальные виджеты значения и Boolean. Документ отдельно по сессиям в panels/main.properties. Запись/action на реальном контроллере пока отключены; интерфейсы предусмотрены, демо-команды работают только на имитаторе.

Обновления используют общий последовательный опрос, отдельного SOX соединения у виджетов нет. Подписки и наблюдения закрываются при завершении представления. Отсутствующий/несовместимый JAR не блокирует редактор. Версия API проверяется при загрузке. Горячая замена модулей не реализована.

Контракт и правила совместимости: PANEL_API_RU.md. Первичные виджеты — основа для дальнейшей разработки, полноценная свободная раскладка и производственные кнопки остаются следующими задачами этого же проекта.
